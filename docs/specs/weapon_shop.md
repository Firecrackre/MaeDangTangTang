# 무기 상점 시스템 기획서

> 이 문서는 노션 원본 "무기 상점 시스템 기획서"를 복원한 것이며, **수치는 실제 구현(as-built)에 맞춰 정합화**했다.
> 무기 상점의 밸런스 상수 SSOT는 코드 측 `RootDesk/MyDesk/Blacksmith/BlacksmithConfig.mlua`이며, 이 문서의 값은 그 파일을 그대로 옮긴 것이다(각 수치 옆에 출처 라인 표기).
> 서버 권위 로직은 `GameManager.mlua`(`RollShop`/`RequestBuyItem`/`RequestRefreshShop`), 표시는 `WeaponShopManager.mlua`(`@Logic`) + `ui/WeaponShopGroup.ui` — **상점 보드/슬롯 전용**이다. 좌 시계·우 메소 상단 HUD는 이 그룹이 아니라 로비/상점/스크래치 공용 `HudGroup`/`HudManager` 소관.

> 무기 등급은 **5단계(커먼/레어/에픽/유니크/레전더리)** 이며, **0단계(증강 미보유) 기본 등급 확률**은 `커먼60 / 레어30 / 에픽9 / 유니크1 / 레전더리0`다(합 100). 레전더리는 기본 상태에서 등장하지 않고, 상위 등급은 증강 '더 좋은 물품 들여오기'로만 개방된다(§10). 구매가는 기본판매가의 1.2배로, **구매가 > 판매가**(큐브로 잠재를 올려야 흑자인 도박성 경제)다. 등급 key(`Rare/Epic/Unique/Legendary`)가 잠재능력 등급과 문자열이 겹치지만 **별개 차원**임에 주의(§6). 초안과 남는 세부 차이는 §17 참조.

---

## 1. 개요

**무기 상점**은 플레이어가 큐브를 사용하기 전, 기본 무기를 구매하는 시스템이다.

상점에는 **랜덤한 종류와 랜덤한 등급**의 무기가 슬롯 단위로 등장한다. 플레이어는 등장한 무기 중 하나를 구매하고, 그 무기에 큐브를 사용해 잠재능력을 뽑은 뒤 판매가를 올리는 흐름을 진행한다.

무기 등급이 높을수록 구매가는 비싸지만 **기본 판매가**도 높아지므로, 높은 등급의 무기는 더 큰 수익을 노릴 수 있는 투자 대상이 된다.

## 2. 목표

| 목표 | 설명 |
| --- | --- |
| 구매 단계의 선택감 강화 | 플레이어가 어떤 무기를 구매할지 고민하게 만든다. |
| 투자 리스크 제공 | 높은 등급 무기는 비싸지만, 성공 시 더 큰 수익을 기대할 수 있다. |
| 반복 플레이 변화 제공 | 매번 다른 종류와 등급의 무기가 등장해 플레이 흐름에 변화를 만든다. |
| 판매가 계산과 연동 | 무기 등급에 따라 기본 판매가가 달라지도록 한다. |
| 업그레이드 시스템과 연동 | 대장 기술(증강)로 높은 등급 무기 등장 확률을 높일 수 있게 한다. |

## 3. 시스템 위치

무기 상점은 게임 흐름에서 **큐브 사용 이전 단계**에 위치한다.

```
상점 무기 등장
→ 플레이어가 무기 선택
→ 무기 구매
→ 큐브 사용
→ 잠재능력 스크래치
→ 판매가 계산
→ 판매 또는 한 번 더 사용하기
```

무기 상점은 플레이어가 큐브를 사용할 대상을 정하는 플레이 흐름의 첫 번째 기점이다.

## 5. 무기 종류

무기 종류는 5종이며, **모두 동일 확률(각 1/5)** 로 등장한다. (`BlacksmithConfig.mlua:97-104`, 추첨은 `GameManager.mlua:144` `RandomIntegerRange`로 균등)

| 무기 종류 | 유효 스탯 | 유효 공격 계열 |
| --- | --- | --- |
| 검(sword) | STR | 공격력, 보스 공격력 |
| 활(bow) | DEX | 공격력, 보스 공격력 |
| 스태프(staff) | INT | 마력, 보스 공격력 |
| 완드(wand) | INT | 마력, 보스 공격력 |
| 단도(dagger) | LUK | 공격력, 보스 공격력 |

무기 종류는 **판매가 계산의 유효 옵션 판정**과 아이콘에만 사용된다. (유효 옵션 세부 판정은 `pricing_calculation.md §8` SSOT)

> 보스 공격력(BATK)은 모든 무기에서 유효 공격 계열로 처리한다. (`BlacksmithConfig.mlua:93`, `IsValidMain` :241)

## 6. 무기 등급

무기 등급은 상점에 등장하는 **무기 자체의 등급**이며, 큐브 사용 후 결정되는 **잠재능력 등급과는 별개의 값**이다. (`BlacksmithConfig.mlua:106` 주석)

| 구분 | 설명 |
| --- | --- |
| 무기 등급 | 상점에 등장하는 무기 자체의 등급 = **"기본 판매가 티어"** |
| 잠재능력 등급 | 큐브 사용 후 잠재능력에 붙는 등급 (판매가 계산의 등급 배수, `pricing_calculation.md §11`) |

무기 등급은 **구매가와 기본 판매가**를 결정한다. 잠재능력 등급은 판매가 계산 단계의 **배수**(`gradeMult`)에 영향을 준다. 두 값은 서로 다른 차원이며 곱해지는 시점도 다르다.

> ⚠️ **key 이름 주의.** 무기 등급 key `Rare/Epic/Unique/Legendary`는 잠재능력 등급(`gradeProb`/`gradeMult`, `potential_determination.md`)과 문자열이 겹친다. 단 코드에서 **별개 테이블**(`weaponGrades` vs `gradeProb`)로 관리되어 기능 충돌은 없다. 무기 등급 = 상점 등장 무기의 기본 판매가 티어, 잠재능력 등급 = 큐브 결과 배수 — 혼동하지 말 것.

### 무기 등급 종류 (5종)

| 무기 등급 | 설명 |
| --- | --- |
| 커먼(Common) | 기본 등급 |
| 레어(Rare) | 커먼보다 높은 구매가와 기본 판매가 |
| 에픽(Epic) | 레어보다 높은 구매가와 기본 판매가 |
| 유니크(Unique) | 성공 시 높은 수익을 기대할 수 있는 무기 |
| 레전더리(Legendary) | 가장 높은 등급으로, 큰 수익을 노릴 수 있지만 구매 부담도 큰 무기 |

> 같은 등급이면 무기 종류가 달라도 구매가·기본 판매가가 동일하다(예: 커먼 검 = 커먼 활 가격). 무기 종류는 유효 스탯·아이콘만 결정한다.

## 7. 무기 등급별 가격

무기 등급별 구매가·기본 판매가는 **등급별 절대 가격**으로 정의한다. **구매가 = 기본 판매가 × 1.2** — 구매가가 항상 판매가보다 20% 높다. (`BlacksmithConfig.mlua:111-117` `weaponGrades`)

| 무기 등급 | 구매가(buyCost) | 기본 판매가(basePrice) |
| --- | --- | --- |
| 커먼(Common) | 30,000 메소 | 25,000 메소 |
| 레어(Rare) | 60,000 메소 | 50,000 메소 |
| 에픽(Epic) | 120,000 메소 | 100,000 메소 |
| 유니크(Unique) | 240,000 메소 | 200,000 메소 |
| 레전더리(Legendary) | 480,000 메소 | 400,000 메소 |

> **경제 설계**: 구매가 > 기본 판매가이므로, 큐브로 잠재능력을 올리지 않고 기본가에 되팔면 **손해**다. 잠재를 성공적으로 올려야 흑자가 나는 도박성 구조다.
> 구매가는 플레이어가 상점에서 지불하는 비용이다. (증강 '가격 협상' 보유 시 실제 지불액은 감소 — §12·§10)
> 기본 판매가는 큐브 사용 후 판매가 계산의 기준값(base)으로 사용된다. (§14)
> ⚠ 시작 메소 40,000이면 시작 시 커먼(30,000)만 구매 가능 — 의도된 초반 게이팅.

> 위 수치는 초기 기준안이며, 플레이테스트로 조정한다. 조정은 `BlacksmithConfig.mlua`의 `weaponGrades`에서만 한다(SSOT).

## 8. 무기 등장 방식

상점 슬롯은 다음 순서로 생성된다. (`GameManager.mlua:128-156` `RollShop`)

```
1. 상점 슬롯 생성 (shopSlotCount = 3)
2. 무기 종류 랜덤 결정 (5종 균등)
3. 무기 등급 랜덤 결정 (RollWeaponGrade)
4. (무기 종류 + 등급) 조합이 이미 있으면 재추첨 (중복 방지)
5. 슬롯에 무기 정보 확정
```

### 무기 종류 등장 확률

| 무기 종류 | 등장 확률 |
| --- | --- |
| 검 / 활 / 스태프 / 완드 / 단도 | 각 20% (균등) |

## 9. 무기 등급 등장 확률 (0단계 = 증강 미보유 기본)

상점에 등장하는 무기 등급은 확률(가중치)에 따라 결정된다. (`BlacksmithConfig.mlua` `weaponGrades.prob`, 추첨 `RollWeaponGradeDetail`/`RollWeaponGrade`)

| 무기 등급 | 등장 확률 |
| --- | --- |
| 커먼(Common) | 60% |
| 레어(Rare) | 30% |
| 에픽(Epic) | 9% |
| 유니크(Unique) | 1% |
| 레전더리(Legendary) | 0% |

> 무기 상점 기획서 §9 기준안 그대로다. **레전더리는 0단계(증강 미보유)에서 등장하지 않으며**, 에픽·유니크·레전더리 등 상위 등급은 증강 '더 좋은 물품 들여오기'로만 확률이 열린다(§10의 단계별 절대 확률표).
> 추첨은 `prob` 가중치를 총합으로 정규화해 결정하므로, 대장 기술 보정(§10)으로 확률표가 바뀌어도 동작한다(0 가중치 허용).
> 위 확률은 초기 기준안이며, 대장 기술과 플레이 테스트 결과에 따라 조정한다.

## 10. 대장 기술(증강) 연동 — "더 좋은 물품 들여오기"

대장 기술 '더 좋은 물품 들여오기'를 보유하면, 상점에 **높은 등급(에픽·유니크·레전더리) 무기가 등장할 확률이 증가**한다. (`BlacksmithConfig.mlua` `betterGoodsGradeProb`·`GetShopGradeProbTable`, 추첨 `RollWeaponGradeDetail`, 배선 `GameManager.RollShop`의 `GetAugmentStage("betterGoods")`)

### 효과 방식 (as-built)

보유 단계에 따라 **단계별 절대 확률표**를 통째로 교체한다(배수 방식이 아님). 0단계는 §9의 기본표, 1~3단계는 아래 표를 그대로 사용한다. (단위 %, 각 행 합 100)

| 단계 | 커먼 | 레어 | 에픽 | 유니크 | 레전더리 |
| --- | --- | --- | --- | --- | --- |
| 0단계 (미보유) | 60 | 30 | 9 | 1 | 0 |
| 1단계 | 45 | 40 | 12 | 3 | 0 |
| 2단계 | 30 | 42 | 20 | 7 | 1 |
| 3단계 | 18 | 38 | 27 | 13 | 4 |

> 추첨은 확률표 값을 총합으로 정규화해 결정하므로 0 가중치(1단계 레전더리 0%)도 그대로 동작한다. 대장 기술의 획득·중복(단계 상승)·최대 단계(3) 규칙은 `blacksmith_upgrade.md`가 SSOT다. 무기 상점은 그 단계 값을 받아 등급 확률표를 고르는 소비자 역할만 한다.

### 상점 추첨 로그 (디버그, 상시)

`RollShop`은 추첨할 때마다 하단 콘솔에 두 줄을 남긴다.

```
[RollShop] 등급 확률표(더좋은물품 2단계): 커먼30%(~30) 레어42%(~72) 에픽20%(~92) 유니크7%(~99) 레전더리1%(~100)
[RollShop] slot1=에픽 스태프(20%, roll=73.4) slot2=레어 검(42%, roll=69.7) slot3=커먼 스태프(30%, roll=12.9)
```

- 첫 줄: 적용 중인 확률표 + 각 등급의 **누적 상한 구간**(`~20`, `~70` …).
- 둘째 줄: 슬롯별 `등급 무기명(등급 확률%, roll=값)`. `roll`(0~100 랜덤)이 첫 줄의 누적 구간 중 어디에 떨어졌는지가 곧 등급 판정 근거다(예: `roll=73.4`는 70~89 구간이라 에픽).

## 11. 상점 갱신

상점 목록은 특정 시점에 새로 생성된다. (as-built)

| 시점 | 처리 | 근거 |
| --- | --- | --- |
| 게임 시작 시 | 상점 무기 목록 생성 | `ResetSession` → `RollShop` (`GameManager.mlua:112`) |
| 무기 구매 후 | 구매한 무기는 작업대로 가져가므로 상점을 새로 채움 | `RequestBuyItem` 말미 `RollShop` (`GameManager.mlua:212`) |
| 새로고침 버튼 | 상점 목록 재추첨 (**메소 소모 없음 — 무료**) | `RequestRefreshShop` (`GameManager.mlua:158-166`) |

### 갱신 처리 기준

- 상점이 갱신될 때마다 각 슬롯의 무기 종류와 등급을 다시 결정한다.
- 이전 상점에 있던 무기는 갱신 후 사라진다(보관하지 않음).
- 게임 오버 상태에서는 새로고침이 거부된다.

> ⚠️ **초안과 차이.** 초안은 "판매 후/파괴 후 갱신 + 유료 새로고침"이었으나, 현재 구현은 **판매·파괴 후 자동 갱신이 없고, 새로고침은 무료**다. 밸런스 확정 시 이 정책을 재검토한다(유료화하려면 `RequestRefreshShop`에 메소 차감 추가).

## 12. 구매 처리

플레이어가 상점 슬롯을 선택하면 구매가 진행된다. **모든 검증은 서버 권위**로 하며 클라이언트 입력(슬롯 인덱스)은 신뢰하지 않는다. (`GameManager.mlua:168-218` `RequestBuyItem`)

### 구매 흐름

```
1. 클라가 슬롯 인덱스를 서버에 요청
2. 서버가 자신의 ShopSlots에서 해당 슬롯의 종류/등급을 읽음(위조 차단)
3. 실효 구매가 계산 (증강 '가격 협상' % 감소 반영 — GetEffectiveBuyCost)
4. 보유 메소가 실효 구매가 이상인지 확인
5. 메소 차감
6. 현재 아이템 등록: CurrentItemId / CurrentBasePrice(=등급 basePrice) / CurrentWeaponGrade
7. 잠재 상태 리셋 → 큐브 사용 가능 상태
8. 상점 재추첨 (RollShop)
```

### 구매 실패 처리

| 상황 | 처리 |
| --- | --- |
| 게임 오버 상태 | 구매 불가 |
| 현재 아이템 보유 중 | 새 무기 구매 불가 |
| 잘못된 슬롯 인덱스 / 슬롯 데이터 없음 | 구매 거부 |
| 보유 메소 부족 | 구매 불가 |

> 증강 '가격 협상'(priceNego)은 구매가를 단계별 **10/18/40%** 감소시킨다(신 기획 `blacksmith_upgrade.md` §6 = 구현 일치). (`BlacksmithConfig.mlua` `augments.priceNego.stages`, 적용 `RequestBuyItem`의 `GetEffectiveBuyCost`, 1000단위 반올림)

## 14. 판매가 계산 연동

무기 상점에서 결정된 **무기 종류**와 **기본 판매가**는 판매가 계산에 사용된다.

| 데이터 | 사용처 |
| --- | --- |
| 무기 종류(CurrentItemId) | 유효 옵션 판정 (`pricing_calculation.md §8`) |
| 무기 등급 | 구매가 + 기본 판매가 결정 (§7) |
| 기본 판매가(CurrentBasePrice) | 최종 판매가 계산의 기준값(base) |

### 연결 방식

구매 시 등급의 `basePrice`를 `CurrentBasePrice`에 저장하고, 큐브 사용 시 이를 `pr.baseOverride`로 판매가 계산에 넘긴다. (`GameManager.mlua:209`, `:281`)

```
최종 판매가 =
(무기 기본 판매가 + 옵션 보너스 총합 + 조합 보너스) × 잠재능력 등급 배수 × 이탈 배수
```

무기 등급은 위 식의 **무기 기본 판매가**에 이미 반영되어 있으므로, 판매가 계산 단계에서 무기 등급을 다시 곱하지 않는다.

> `pricing_calculation.md §7`의 기본 판매가 티어(저가 25,000 / 중가 50,000 / 고가 100,000)는 무기 등급 커먼/레어/에픽과 일치한다. **유니크 200,000 · 레전더리 400,000**은 그 3티어를 넘어 확장된 값이므로, 판매가 문서의 티어 표와 함께 참고한다.

## 17. 원본 초안과 실제 구현 대조 (인수인계용)

노션 원본 초안 대비, 이 문서/코드가 **일치시킨 항목**과 **의도적으로 다르게 둔 항목**을 정리한다. 이 문서와 `BlacksmithConfig.mlua`가 함께 SSOT다.

### 초안과 일치시킨 항목

| 항목 | 값 |
| --- | --- |
| 무기 등급 체계 | 5단계 커먼/레어/에픽/유니크/레전더리 (초안과 동일) |
| 최저 등급(커먼) 구매가 | 30,000 / 판매 25,000 (초안 §7과 동일, 구매가 > 판매가) |
| 0단계 등급 등장 확률 | **커먼60/레어30/에픽9/유니크1/레전더리0** (무기 상점 기획서 §9 기준안과 일치) |
| 대장 기술 효과 방식 | **단계별 절대 확률표**(§10 표) — 무기 상점 기획서 §10·`blacksmith_upgrade.md` §6과 일치 |

### 초안과 다르게 둔 항목 (구현/설계상 의도)

| 항목 | 원본 초안(노션) | 이 문서/코드 |
| --- | --- | --- |
| 판매가 티어링 | 기준가 × 등급 배수(1.2/1.5/2.2/3.5) | **코드식 절대 티어**(25k/50k/100k/200k/400k, ×2 배증). 구매가만 판매가×1.2로 초안 비율 유지 |
| 슬롯 수 | 기본 1 + 랜덤 4 = 5개 | **3슬롯**(`shopSlotCount = 3`) — 로비/증강 UI와 균형 맞춘 축소 |
| 상점 갱신 | 유료 새로고침 + 판매/파괴 후 갱신 | **무료 새로고침 + 게임시작/구매 후 갱신**(판매·파괴 후 갱신 없음) |
| 슬롯 중복 | 허용 | 동일 (종류+등급) 조합 **중복 제거** |
| 예외: 등급 데이터 없음 | 레어 등급으로 기본 처리 | **구매 거부** |

> ⚠️ 무기 등급 key `Rare/Epic/Unique/Legendary`는 **잠재능력(큐브) 등급**(`BlacksmithConfig.gradeProb` = 60/28/10/2, `gradeMult` = 1.0/2.0/3.5/5.0, `potential_determination.md`)과 문자열이 겹친다. 별개 테이블·별개 차원이므로 혼동하지 않는다(§6).
